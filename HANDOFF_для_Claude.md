## Що це за продукт
Тренажер для фармацевтів: працівниця грає роль себе за касою, модель грає **клієнта
інтернет-замовлення** і одночасно **суддю**, який фіксує, що клієнт погодився купити.
Мета навчання — фармзаміна на власну марку (ВТМ) і додатковий продаж.
Оцінка = приріст бонусу чека над початковим замовленням.

Спочатку це був артефакт у Claude, який працював лише на акаунті Оли.
Переписано у звичайний сайт на GitHub Pages, модель — `qwen/qwen3.8-27b` через Groq,
ключ ховається за проксі Cloudflare Worker.

## Як влаштовані дані
**catalog.json** → `categories: { ключ: { label, items:[…] } }`
Товар: `c` код (унікальний глобально) · `n` назва · `b` **бонус ₴ — на ньому весь підрахунок**
· `p` довідкова ціна, у логіці не бере участі, часто `null` · `k` ВТМ / ЗФ / «—».

**scenarios.json** → `scenarios: […]`
`id` · `grp` група · `no` номер замовлення (`null` = оформлення на місці) · `title`
· `cats` **категорії, чий асортимент бачить модель — що не тут, того для неї не існує**
· `main` головна категорія · `order` коди в замовленні · `open` перша репліка клієнта
· `who` / `mood` / `mode` · `goal` навчальна ціль · `bv` / `bm` ідеальний чек під ВТМ / СТМ
· `noSale` правильна дія «не міняти» · `trap` пастка.

Орієнтир приросту = `сума b по bv` − `сума b по order`.

## Жорсткі правила, які легко порушити
1. **Кожен код у `order` / `bv` / `bm` мусить існувати в каталозі.** Інакше падіння.
2. **Ці коди мусять лежати всередині `cats` сценарію**, інакше модель їх не побачить
   і ніколи не запропонує.
3. `main` мусить входити в `cats`.
4. Ідеал має бути дорожчий за замовлення, інакше орієнтир від'ємний.
5. У 9 із 43 сценаріїв бонус замовлення дорівнює **0** — клієнт замовив оригінал.
   Це не помилка даних.
6. Після будь-якої правки: `node ae_validate.js` → має бути `✗0`.

## Модель
`qwen/qwen3.8-27b` на Groq. Режим **instruct**, не thinking:
`reasoning_effort:"none"` · `reasoning_format:"hidden"` · `temperature:0.7` · `top_p:0.8`.
Підтримує **JSON Schema Mode** — саме тому в `config.json` лежать `schemas.turn`
і `schemas.debrief`. Модель структурно не може повернути не-JSON, тому в промптах
**немає** прохання «відповідай лише JSON» — це робить схема. Не додавай його назад.

Ціна: input $0.80 / млн, output $4.00 / млн. Одна зміна з 5 замовлень ≈ $0.045.
`presence_penalty` стоїть 0.3, хоча Groq радить 1.5: у нас строгий JSON із
повторюваними ключами, високий штраф може ламати структуру.

## Двигун розмови
В `index.html` два двигуни з однаковим контрактом:
```
engine.turn(scenario, history) → {reply, cart, ended, endReason, feedback}
```
- `engineLive` — справжній Groq. Працює за замовчуванням.
- `engineMock` — заглушка з чотирьох реплік. Вмикається адресою `?mock=1`.
  У цьому режимі з'являється жовта панель ручного складання чека.

`callModel()` — єдина точка виходу в мережу. Якщо в браузері є ключ, іде прямо
на Groq; якщо ключа немає — на `config.model.endpoint` (Cloudflare Worker, крок 3).

Чек, який повертає модель, **фільтрується** по асортименту сценарію: чужий код
зламав би підрахунок. Не прибирай цей фільтр.

## PWA-захист — не прибирати
У CSS є блок «анти-веб-патерн»: `user-select:none` на body, `touch-callout:none`,
`tap-highlight-color:transparent`, `overscroll-behavior:none`, `touch-action:manipulation`,
`user-scalable=no` у viewport. Він робить так, щоб застосунок не видавав себе за
сторінку. Виняток зроблено для `input`/`textarea` і для `.turn`/`.brief dd`/`.tape` —
цей текст має сенс копіювати.

**`font-size:16px` у полях вводу — обов'язково.** Менший розмір змушує iOS
зумити сторінку при фокусі, і назад вона не повертається.

  вона їх вивіряла. Міняй тільки на прямий запит і показуй різницю до/після.
- Не пропонуй платні сервіси без потреби. Бюджет проєкту — кілька доларів на місяць.
