## §2 Правила, що народились у сесії — повним текстом

**2.1 · Відмова інструмента пошуку перекладає пошук на ручний перебір —
і перебір оголошується неповним.**
Мікроскоп (wsd 1.9, вісь 3) вимагає шукати **за ознакою**, а не за іменем.
Він не каже, що робити, коли інструмент пошуку за ознакою відмовив. У цій
сесії GitHub API впав на ліміті, і пошук по репо тихо виродився в перебір
трьох імен, відомих із самері. Вісь 3 при цьому отримала ✓ — бо намір був
правильний. Наслідок: `ПОЧНИ_ЗВІДСИ.md` не знайдений, написаний дубль.
Правило: відмова інструмента не скасовує вісь, а **міняє форму відповіді** —
«перебрано N імен, повного списку не отримано», і це саме по собі дефект
плану, а не примітка. ✓ на осі, отриманий неповним пошуком, — хибний ✓.
⚠ Перед вливанням у wsd звірити з 1.9 і 12.17: це розширення осі 3, не новий
номер.

**2.2 · Фікс втраченого порту приходить із гейтом, або це не фікс.**
Втрата при переносі небезпечна тим, що нічого не падає: рядок зник, застосунок
працює, дефект живе сесіями. `mood` пролежав загубленим від S5 саме так —
у `smoke_ui_v1.js` не було **жодного** твердження про брифінг, і бути не могло
інакше: якби воно було, втрата б не сталась. Тому повернення загубленого без
сторожа — запрошення втратити втретє.
Правило: повертаючи втрачене, у тому самому ході постав твердження на місце
втрати **і** інʼєкцію, що цю втрату відтворює. Дельта тверджень і дельта
`--inject` називаються обидві — інʼєкція, яка не змінила ✗, означає, що нове
твердження декоративне (1.15, пастка 4).

**2.3 · Показане моделі ≠ показане людині; розбіжність читається як дефект
характеру.**
`mood` їхав у промпт клієнта від початку (`index.html:381`) і не малювався на
екрані (`891`). Модель грала заданий опір, людина його не бачила і читала
будь-яку сухість як «клієнт непривітливий взагалі» — тобто скаржилась на
одноманітність там, де насправді була **невидимість**. Правило: для кожного
поля даних, що впливає на поведінку моделі, назвати, чи бачить його людина;
розбіжність — окремий предмет, а не дрібниця розкладки. Дешевий фікс екрана
перевіряється **перед** правкою промпту: він може зняти симптом цілком.

## §3 Редактор — рішення прийнято (варіант «в»)

**Форма.** Редактор сценаріїв усередині застосунку → Cloudflare Worker →
**коміт у репозиторій** через GitHub API. Токен GitHub живе у воркері поруч
із ключем Groq. Оля не бачить ні JSON, ні GitHub.

**Обов'язково:** воркер **проганяє той самий валідатор** перед комітом.
Не другу копію правил, не «схожу перевірку» — той самий набір, що й
`tools/ae_validate.js` і що й браузерна перевірка 6а.

**Чому не інші два.**
*(а) редактор → файл на завантаження:* знімає ризик синтаксису, але транспорт
лишається на людині.
*(б) редактор → Cloudflare KV (крок 5):* правка живе миттєво, GitHub не
потрібен — ціна: **два джерела правди**, репо і KV. Це рівно та хвороба, від
якої проєкт уже тікав.
*(в):* джерело правди лишається одне — репо, з історією змін. Надбудова ~40
рядків поверх наявного воркера; код куратора вже є в `config.json`
(`curatorCode`).

**Порядок.** Серце редактора — логіка валідатора в браузері, тобто **6а**.
Спершу 6а, потім «в» як надбудова над готовим, а не з нуля.
