## §2 Правила, що народились у сесії (повним текстом, 14.29)

**П116 · Файл знахідок стенда не йде в архів, доки його вироки не живуть у SPEC і коді.**
*Тригер.* Порт стенда в продукт завершено (для A2 — D2) або файл знахідок стенда (П112) кандидат в архів.
*Дія.* Кожен вирок В-N і рішення з файла знахідок переносяться (1) у SPEC — розділ «<екран> · логіка екрана» людською мовою: що, звідки дані, навіщо; (2) у код — коментар із посиланням `/* В-N */` біля місця, що його реалізує.
*Детектор.* Кожен В-N із файла знахідок грепається в SPEC **або** в коді; нуль входжень = файл лишається живим. Лічба — інструментом.
*Межі.* Сирі заміри проходів (таблиці ✓/✗) у SPEC не переносяться — лише рішення. Файл після перенесення — в архів, не видаляється.
*Дім.* Правило продукту AE; у пакеті «цикл роботи зі стендом» для ядра.

**П117 · Детектор проходу доводить, що вміє бачити ✗.**
*Тригер.* У скрипт проходу (П115) додано або змінено крок.
*Дія.* (1) Новий крок проганяється на **попередній версії** стенда (де вада ще є) і мусить дати ✗; крок, що дає ✓ на обох версіях, — не детектор. (2) Перший ✗ на новій версії спершу розбирається «вада чи детектор» — із заміром, до будь-якого виправлення стенда. (3) Кадр оком (П115) — обов'язковий для кожного елемента, який змінювався, навіть при 100 % ✓: геометрію й перекриття скрипт перевіряє лише тим, що в нього закладено.
*Детектор.* У звіті ходу є рядок «негативний контроль: <версія> — ✗ на кроках …» і перелік кадрів, переглянутих оком.
*Межі.* Для кроків без попередньої версії (новий екран) — штучно зламана копія (одна заміна) замість попередньої.
*Дім.* Доповнення П115; у пакеті для ядра.
*Народилось:* S78 — 4 детектори збрехали (Python `round` ≠ JS `Math.round`; край картки замість рядка; «Каталог»/«Каталозі»; ✓ на зламаній кнопці «Групи», зловлено кадром).
