# AE-Simulator

Тренажер розмови за касою для фармацевтів. Працівниця грає саму себе,
модель грає клієнта інтернет-замовлення і суддю, який розбирає розмову.

**Застосунок:** https://konst-andre.github.io/AE-Simulator/

---

## Олю, тобі сюди

Усі людські тексти лежать в одній теці — **[`ДЛЯ_ОЛІ/`](ДЛЯ_ОЛІ/)**:

| файл | що це |
|---|---|
| [`ПОЧНИ_ЗВІДСИ.md`](ДЛЯ_ОЛІ/ПОЧНИ_ЗВІДСИ.md) | **починай з нього.** Що в проєкті твоє, як вносити правку, чого не чіпати |
| [`ЖУРНАЛ_ЗМІН.md`](ДЛЯ_ОЛІ/ЖУРНАЛ_ЗМІН.md) | що змінювалось у продукті, збірка за збіркою |
| [`HANDOFF_для_Claude.md`](ДЛЯ_ОЛІ/HANDOFF_для_Claude.md) | для AI-асистента, не для читання очима |

Якщо звертаєшся до AI-асистента — прикріпи йому два файли:
`HANDOFF_для_Claude.md` і `ЖУРНАЛ_ЗМІН.md`.

## Що де лежить (коротко)

```
index.html                 застосунок цілком: оболонка + механіка
config.json                налаштування і схеми відповідей моделі
data/catalog.json          товари
data/scenarios.json        сценарії розмов
prompts/                   промпти клієнта, судді, розбору
tools/ae_validate.js       гейт цілісності даних
tools/smoke_*.js           смоук-тести (jsdom)
worker/ae-proxy.js         проксі до моделі; ключ живе там, не в браузері
ДЛЯ_ОЛІ/                   людські документи
```

Кожен push у `data/`, `config.json` або `tools/ae_validate.js` проганяється
гейтом (`.github/workflows/perevirka.yml`). Червоний хрестик біля коміту
означає: правка зламала дані, застосунок її не візьме.
